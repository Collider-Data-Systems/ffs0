Interface Principles

Asset health over raw logs

Dagster asset checks and freshness patterns

Expose pass/warn/fail gates, runtime metadata, artifact paths, and next actions as structured materialization metadata.

Lineage stays first-class

Data orchestration lineage and materialization UIs

Show G-ingest, F-session, and F-visual stages separately so operators can see where evidence, context, and renderers diverge.

Graph UI needs selection semantics

Cytoscape.js element data, selectors, layouts, and tap/select events

Keep the static Graphviz artifact for review, but shape the interactive renderer around typed node data, style selectors, search/focus controls, layout controls, selection events, and an inspector panel.

Warnings are design signals

CI/CD quality gate practice

Treat warn as a usable MVP with named next gates, not as hidden debt or a failed run.

Renderer Candidates

Graphviz DOT/SVG keep

MVP baseline: deterministic, local, reviewable in git, already wired through export_t200plus_projection.jl

Cytoscape.js next

Best next fit from Context7 scan: accepts graph elements JSON, supports selectors/styles/layouts, and has selection/viewport events for node inspection.

Cytoscape layout extensions later

Dagre and cose-bilkent are useful follow-ups when the inspector needs hierarchy or cleaner compound layouts; keep built-in Cose/Grid/Circle/Breadthfirst/Concentric for the local no-build dashboard.

svg-pan-zoom defer

Good library fit for polished pan/zoom on static Graphviz SVGs, but the generated dashboard keeps native controls so offline/local file review still works.

vis-network fallback

Quick node/edge DataSet setup and clustering; useful if the first interactive prototype should be very small.

force-graph later

Good for larger exploratory graphs with pan/zoom/drag interactions, but less semantically structured than Cytoscape for typed HG inspection.

Sigma.js + Graphology later

Strong for high-volume read-only exploration and graph analytics pipelines; less direct than Cytoscape for typed relation selectors and inspector-first workflows.

GraphMakie + Graphs.jl analysis path

Best Julia-side option when metrics, layouts, or notebooks need to stay inside the Julia process; keep generated JSON as the browser/dashboard contract.

ELK / Dagre hierarchical layout next layout extension

Useful for F/G pipelines, WF21 causality, and Calendar/recommendation lineage once the local dashboard can bundle layout extensions cleanly.

Graphview Stack Notes

Renderer separation

Keep graph-artifact JSON as the contract. Graphviz SVG, Cytoscape, Julia notebooks, and any future WebGL renderer should all consume the same selected nodes and relations.

Static proof plus interactive inspection

Use DOT/SVG for deterministic review and diffable artifacts; use Cytoscape for search, filtering, focus, relation metadata, and operator triage.

F/G semantics in data

Encode F/G role and relation-family metadata on elements before rendering, so the UI can expose projection, ingest, authority, and lineage meaning without parsing labels.

Julia analytics boundary

Run graph metrics and lens checks in Julia where the pipeline already lives; avoid making the browser compute truth that belongs in the generated artifact.
