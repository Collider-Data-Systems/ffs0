## Motivation (Sam's functional framing)

- Users **delegate agents** to **populate workspaces** (the renamed `session`).
- The **purpose rules the workspace** (directional intent).
- **persona is an outcome of a function of the purpose** — derived, not assigned.
- External `channel` surfaces (Google Workspace, GitHub) are **F-projections** of `agent` nodes onto concrete identities.
- An application/domain (e.g. `my-tiny-data-collider`) is a durable locus where domains, DNS, websites, kernels, Workspace/GitHub/Calendar/tunnel surfaces are facets of one topology → a **manifold**.

## Proposed deltas

### D1 — `manifold` (new node category), derived-view-first  ✅ RATIFIED (T=219): adopt as new category
- Carrier for an application/domain topology.
- **Stage 1 (3.16.2-compatible):** model as a *derived view* over existing `group` + purpose/session/channel/projection data. No new type yet.
- **Stage 2 (4.0):** **promote to a first-class node type** — Sam ratified `manifold` as a new category, not a perpetual derived view. Stage 1 stays the on-ramp; promotion gated on the explicit reviewed migration (guard below).
- Example: `manifold:my-tiny-data-collider` over `group:my-tiny-data-collider`.

### D2 — `session` → `workspace` rename, alias-first (NO hard rename)  ✅ RATIFIED (T=219): workspace, alias-first
- Collides with **Google Workspace** (a live `channel` surface) and VS Code "workspace".
- Do **not** hard-rename the HG type in one jump: projection/UI alias first, migration plan second.
- ~~Open question~~ **Resolved (Sam, T=219): the term is `workspace`** (not `occasion`/`context`). Alias-first: add `workspace` as the 4.0 term, keep `session` as a read-alias, no topology change. The invariant is unchanged — **purpose × occupant × scope evaluated-present**.

### D3 — `persona = Φ(purpose)` as a `derivation`, not an authority principal  ✅ RATIFIED (T=219): as drafted
- `persona := reify( fold_Φ( purpose ↓ scope ) )` — consumes purpose/session/capability/history/surface-affordance evidence, produces a persona claim/view.
- Carrier: `derivation` (v3.14) — already the right type for reified session-internal inference.
- Keep `agent` as the **operational principal**; §M11/§M12 authority stays on agents + sessions. Persona is derived, never an authority node.
- Provenance: `purpose —WF21 causes→ persona` (acyclic).

### D4 — `presents-as` (new relation, agent ↔ persona) — the one genuinely-new primitive
- An `agent` *presents as* a `persona`. Kept distinct from:
  - WF19 `has-occupant` (`session has-occupant agent`) — occupancy.
  - WF02 `delegates-to` (`user/group delegates-to agent`) — delegation.
- So: an agent **occupies** a session, **may present-as** a persona, and **may be delegated** work — three different facts.

### D5 — `channel.kind` additions (enables the channel-inventory work)
- Add explicit kinds: `domain`, `dns-zone`, `cloudflare-zone`, `cloudflare-tunnel`, `access-app`, `registrar`, `website-endpoint`.
- Explicit ontology migration, not overloading a generic kind.
