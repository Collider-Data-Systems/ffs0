## §1 The space

**Definition.** A *placement situation* is a triple `(P, S, r)`:
- `P` — a small category of **presentation objects**: things a human can point at.
- `S` — a small category of **semantic objects**: things the log can name.
- `r ⊆ Ob(P) × Ob(S)` — the **realization relation**.

Stated this way, neither side determines the other, which is the honest starting point. The design question is not "what is the functor" but **what structure `r` can be upgraded to, given the data**.

The ladder, weakest to strongest, with what each rung requires and whether the data licenses it:

| rung | requires | status here |
|---|---|---|
| bare relation | nothing | **this is the current state** |
| span `P ← M → S` | a category `M` of placement facts | available now (`M` = the graph of `r`, i.e. the manifest) |
| profunctor `P^op × S → Set` | functorial action on both sides | **blocked** — needs per-window semantic data, which does not exist (§5) |
| functor `P → S` | total object map + morphism map | **refuted on the real data** (§5) |
| fibration `p: E → B` | a functor plus cartesian lifts | refuted a fortiori |

Everything below is the evidence for that last column. The useful output of this note is not `L_p` itself — it is knowing which rung you are standing on and what the next one costs.

## §2 `P` — the presentation category

**Definition.** Objects are presentation elements; morphisms are generated by **containment** (`x ≤ y` = "x is contained in y"). `P` is a poset. Whether it is a *forest* is a separate question, answered below.

**Instantiation.** D7 doctrine lists six levels. Three of them have zero instances:

| D7 level | instances |
|---|---|
| workstation-surface | **0** (`host` is a scalar field, not an object) |
| virtual-desktop | 14 |
| window | 24 |
| tab-group | **0** (degenerate — exactly one per browser window, named at runtime from `?surface=`) |
| browser-tab | 51 url entries (30 distinct strings) |
| harness-pane | **0** (a VS Code window's panes are invisible to the manifest) |

**`|Ob(P)| = 14 + 24 + 51 = 89`, and `P` is depth 3, not 6.** The D7 table describes an aspiration; the manifest instantiates half of it. Window kinds: 14 browser + 10 process.

### The monitor question

Monitors are declared **once globally** (4 slots: left / center-left / center-right / right → `\\.\DISPLAY1/3/2/4`), and each window carries one `monitor_slot`. Occupancy is **{1: 14, 2: 5, 3: 4, 4: 1}** — slot 1 is shared by all 14 desktops.

If monitors enter the containment order above windows, every window acquires two incomparable upper bounds (its desktop and its monitor) with no join object — "the region of desktop 4 on monitor 2" is not a thing. **So the monitor table breaks the tree, not the order.** `P` remains a poset; it stops being a forest.

**`L_p` forgets the monitor grading** — and this is derived from the manifest, not imposed. Its own `identity_rule` reads: *"desktop_id is the stable local key; index and name are observed labels. Window coordinates and browser tabs are cache state, never HG identity."* `monitor_slot` is the coarse form of window coordinates.

Testable consequence: **the fibers of `L_p` are closed under changing `monitor_slot`.**

One number recorded because it is true today and will stop being true: `(desktop_id, monitor_slot)` is injective — **24/24 distinct**, filling 24 of 56 cells. Nothing in the schema forbids two windows of one desktop on one slot, and real desktop use does it constantly. This holds by luck, same class as the two normalizers in §9.

### Three keys on one object

| key | declared as | actually used by |
|---|---|---|
| `desktop_id` (GUID) | *"the stable local key"* | nothing at runtime |
| `index` | *"observed label"* | four other configs — and stale in all four (§9) |
| `surface_key` | (undeclared) | **the runtime** — `Start-Z440SessionDesktops.ps1:321` appends `?surface=<key>` |

The manifest declares as identity the one key the runtime does not use. Recorded as a defect, not a nit: identity discipline is what makes any of the rest well-defined.

## §3 `S` — the semantic category, and where it lives

**Definition.** Objects are nameable semantic entities; morphisms come from relations. The design choice is what "nameable" means when the log is not one log.

Three candidate codomains, with the cost of each measured rather than argued:

| option | cost |
|---|---|
| **(a) one engine's fold** | `L_p` is partial: **6 of 23 distinct references have no object** (§9). Functoriality can only be discussed after deleting rooms 5, 6 and 12 from the domain. |
| **(b) the federated union** | Not computed anywhere. Three sovereign logs (Z440 643 · hp-laptop ~1603 · ProDesk 29) with no merge; twin-sync (§M9) unbuilt. Worse, the router fan-in currently duplicates relation URNs (T=264 finding), so the union is not even idempotent on relations. Defining `L_p` against (b) is defining it against an object that does not exist. |
| **(c) the URN namespace as a free category** | **Recommended**, with the honest limits below. |

**Ruling: (c) for objects, (a) for morphisms, plus a residence function.**

- `Ob(S)` = all syntactically valid URNs (grammar: the per-type `urn_pattern` in `ontology.json`).
- Morphisms = the free category on a **declared** generator graph read from the Z440 fold (§4).
- `ρ: Ob(S) → {z440, hp-laptop, hpprodesk, ∅}` records which fold currently holds a node with that name.

This extends existing doctrine rather than importing any: `ontology.json.free_category_note` already states the ontology *is* the free category on its generators, with no equations beyond `port_color_compatibility` and CI-5.

**What (c) does not buy — stated plainly, because "free category" sounds like it solves more than it does:**
- It buys **totality on objects only**. `group:my-tiny-data-collider` becomes a legitimate object with `ρ = ∅` instead of a crash. Rooms 5, 6 and 12 start producing a number instead of an error.
- It buys a **new checkable invariant**: `ρ(x) ≠ ∅`, "the name denotes". That is the 6-missing-reference defect made measurable.
- **It does not buy the order.** Names are free; morphisms still come from relations, and relations live in a sovereign fold.

> **[CONJECTURE — new, and the productive one]** With three sovereign logs and no gluing, `S` is not one category but a **presheaf over a three-engine site**, and §M9 twin-sync is exactly the missing **descent condition**. This is the one place in this note where the categorical framing earns its keep rather than decorating: it says what twin-sync *is*, not merely that it is absent. Not checkable until twin-sync exists.

## §4 The order on `S`

**Ruling: no order exists. One must be declared. Declaring it means choosing a polarity for each generator — and one of the four required polarities is a flip.**

Monotonicity is the whole content of "L_p is a functor", and it is meaningless without an order on the codomain. This section is therefore a prerequisite, not a detail.

| id | generator | polarity (`above → below`) | live instances | verdict |
|---|---|---|---|---|
| g1 | WF03 `hosts` | workstation ⊒ kernel | 4 | keep |
| g2 | WF18 `spans` | manifold ⊒ {channel, session, purpose, group} | 9 | keep |
| g3 | WF19 `opens-on` | **kernel ⊒ session** | 10 | keep — **polarity flips** |
| g4 | WF19 `has-purpose` | session ⊒ purpose | 7 | keep |
| g5 | WF18 `composes`, restricted to purpose→channel | purpose ⊒ channel | **0** | **declared, empty** |
| g6 | `parent_channel_urn` | channel ⊒ channel | 5 | **a property carrying topology** |
| — | WF19 `has-occupant` (7), WF01 `owns` (17), WF02 `member-of` (10), `governs` (7) | — | 41 | **excluded — this is A1 identity, not placement** |

Three consequences this table forces:

**g3 requires a polarity flip.** `opens-on` points session→kernel, but the D7 chain puts the engine *above* the workspace, so the order edge runs kernel→session. `has-purpose` points session→purpose and the chain agrees. Mixing the two without declaring polarity produces a graph that is not graded. This is the precise answer to *"does S have an order?"* — it has one only after four polarity declarations, one of which contradicts its own arrow direction.

**g5 is where the chain dies, and it is cheap to fix.** The D7 chain manifold → engine → workspace → purpose → channel is walkable at levels 1–4 and stops at purpose→channel. WF18 already declares `src_types: [program, purpose, manifold]` and `channel` among its `tgt_types`. Of the **9** live `composes` relations, **0** are purpose→channel. The pair exists and is empty. Closing it costs LINKs only — no ontology bump. This is the highest-leverage single fact in this note.

**g6 is a doctrine violation already on the books.** `parent_channel_urn` is a URN-valued *property* carrying containment between two nodes, while `topology_property_boundary` states *"Relations are truth. Properties never duplicate topology"* with an exception list of exactly `owner_urn` and `sender_urn`. Either the channel hierarchy is topology and needs a relation, or the order has no channel-internal structure and the 5 github channels are 5 incomparable elements. Both readings are stated below rather than quietly picking one.

### The resulting DAG — measured both ways

| variant | vertices | edges | cycles | maximal elements |
|---|---|---|---|---|
| **order proper** (relations only, g1–g5) | **31** | 30 | **0** | **2** — `manifold:my-tiny-data-collider` (reaches 10), `workstation:hp-z440` (reaches 21) |
| with g6 (admitting the property as topology) | 33 | 35 | 0 | 3 — adds `channel:github.collider-data-systems` |

Two facts to carry forward:

- **`S` has no top.** Under either variant there are ≥2 maximal elements. Any statement of the form "everything lands under the manifold" is **false as measured**: the manifold reaches 10 of 31 vertices; the workstation reaches 21; they overlap below.
- **The ordered part of `S` is 31 of 294 nodes = 10.5%.** Everything else — 55 knowledge_item, 39 shard_rule, 30 derivation, 24 grammar_fragment, 18 program — sits outside the placement order entirely. Saying "`L_p: P → S` where `S` is the fold" overstates the codomain by roughly a factor of nine.

Acyclicity (0 cycles) means antisymmetry holds and a partial order exists on the transitive closure.

## §5 `L_p` and the fourteen-room test

### The object map

```
L_p(desktop d) = d.anchor_urn      partial: 10 of 14 anchored
L_p(window w)  = undefined         windows carry label / kind / monitor_slot / exe / args — all substrate
L_p(url u)     = undefined         a string
```

**This is the headline.** The manifest carries exactly one semantic pointer per desktop (`anchor_urn`) plus two decorations (`actor_urn`, `engine.urn`). **Below the desktop level there is no semantic data at all.** A functor must be defined on every object of its domain. Therefore:

> **`L_p` does not exist as a functor on `P` today.** What exists is a partial function defined on one of three levels — rung 1 of the §1 ladder, with rung 2 (the span) immediately available.

Two ways to complete it, both named so neither is smuggled in:

- **Collapse** — `L_p(window) = L_p(its desktop)`, likewise urls. Then `L_p` factors through `P → Desk` and every containment morphism maps to an identity. **Functoriality becomes vacuous.** Anyone who reports "L_p verified functorial" against this completion has verified nothing. Stated here so that claim cannot be made later by accident.
- **Rules** — derive `L_p(url)` by matching `channel.source_uri`. Measured: **8 of 51 url entries match exactly** (0.157). With declared rules (`:<port>/healthz` → engine, `sidepanel.html` → the Pilot channel, `keep.google.com`, `calendar.google.com`) it reaches roughly 33/51, leaving ~18 external references needing channel nodes that do not exist.

Two independent failures, both structural:

1. **No shared top.** `P`'s top is a machine; `S`'s maximal elements include a manifold. A machine hosts many manifolds and a manifold spans many machines, so no single monotone map relates the two hierarchies. This is not a data defect — it is the shape of the problem.
2. **Not level-preserving.** One surface level (virtual-desktop) lands on **three different semantic depths — {0, 1, 2}** — under two different maximal elements. Level-preservation fails outright.

> **Consequence for the T=218 conjecture.** *"The surface poset is fibered over the semantic poset"* is **refuted in its smallest concrete case**: the cheapest candidate functor is monotone on 4/14 and level-preserving on 0/14. The general claim could still be rescued by adding data (the note says how, §10); the current instance is dead. Downgraded in §8.

The adjacent defect is sharper: **rooms 13 and 14 encode the same public/private distinction in two different slots** — room 13 puts posture in the *anchor* (`session:public-demo`, actor `user:anon`), room 14 puts it in the *actor* (`user:sam`, anchor = the manifold). These rooms have real referents — 6 external urls — and the ontology already carries `channel.kind = web` with one live instance (`channel:web.labs-flow`). ### On η — the doctrine measures the wrong side

The T=218 note says *"the unit η: x → G(F(x)) measures round-trip loss; a projection is lossless exactly where η is iso."* That presupposes an adjunction F⊣G, and **there is no G**. To get a number you must define one, and the definition decides what you measure. Setting `F(s) = Fib(s)` and `G(d) = anchor(d)`:

- `η_s : s → G(F(s))` is iso ⟺ `|Fib(s)| ≥ 1` — that measures **coverage**, and it is trivial.
- `ε_d : F(G(d)) → d` is iso ⟺ `|Fib(anchor(d))| = 1` — that measures **room recoverability**, and it is the interesting one.

**The doctrine's η line measures the trivial side.** Corrected here; not a defect in the idea, a defect in which arrow was named.

```
A  anchor coverage       = anchored rooms / rooms                 = 10/14 = 0.714
B  anchor denotation     = ρ(anchor) ≠ ∅ / anchored rooms         =  7/10 = 0.700
C  room recoverability   = |Fib(anchor)| = 1 / anchored rooms     =  8/10 = 0.800
```

## §7 Reify ruling — reify the objects, defer the relation

The doctrine gate for D8 is explicit: *"promote to a relation port-pair only if the projection pipeline needs to **write** it."*

**Measured, not argued:** `Start-Z440SessionDesktops.ps1` and `New-Z440SurfaceCache.ps1` make exactly one kind of network call between them — `Invoke-RestMethod` GET on `health_url`. **Zero POSTs, zero `/rewrites`.** The gate is not met.

**Ruling: do not reify D8 now.**

1. Gate not met, by measurement.
2. **The binding constraint is not the relation — it is that the objects do not exist.** You cannot write `X realizes Y` when `X` has no node. The `channel.kind` surface enum has been available since 4.0.0 and has **0 instances**.
3. Correct the cost estimate while here, because the docs overstate it: `additional_port_pairs` **are** consumed by the loader (`internal/operad/loader.go`, enforced in `validate.go` with per-pair src/tgt type checks). Reifying D8 is an `ontology.json` edit plus two `port_color_map` entries — **not a Go change**. Cheaper than assumed, which is a reason to do it deliberately rather than by default.
4. An option nobody has named: **WF19 `pins-urn` has `tgt_types: ["*"]`** and 33 live instances. Once surface channels exist, `session pins-urn surface-channel` carries placement with **zero ontology change**. Semantically weaker — a pin is not a realization — but available today.

**The tension, named rather than papered over:** doctrine says surfaces are *"observed, not authored"*, and a hand-written ADD is authoring. The mitigation already exists in the ontology — mint with `substrate: external-channel` + `substrate_anchor_urn`, the fields that mark a channel as observed rather than native (5 channels already use them).

**Where this lands institutionally.** `ontology.json.ci2_projection_registry` states: *"Projections not listed here are lossy — valid for S4 display only, not for authority."* **`L_p` is not CI-2 compliant (monotone 4/14, proven above). It is therefore an S4 display projection, not an authority path.** Using the project's own register rather than inventing a verdict.
