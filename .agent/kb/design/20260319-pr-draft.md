### PortBinding — OBJ24 Candidate

A port-to-port (PTP) binding is currently implicit in `TypeSpec.PortTargets`. Proposed:
reify as a first-class S1 inventory node:

```
urn:moos:ptp:user.owns→any.child

ADD(urn:moos:ptp:user.owns→any.child)
LINK(ptp_node, "params", benchmark_node, "bench")
LINK(ptp_node, "params", provider_node, "config")
LINK(ptp_node, "params", req_schema_node, "req")
LINK(ptp_node, "params", resp_schema_node, "resp")
```

The PTP node comes as a **package**: 4-tuple signature + parametrization (provider,
benchmarks, req/resp schema). This is how the superset maps into the user's HG — the
wire type made visible, queryable, and metricated. Task 033's saturation lens is the
runtime foundation: it already detects LatentBindings (gap ports) and ActiveBindings
(wired ports). The Schema tab in Explorer 2.0 renders the PortBinding inventory view.

---

### BindingCategories — Dynamically Composable Subcategories

Any combination of bound and unbound PortBindings defines a **BindingCategory** —
a full subcategory of C with its own algebra. Not pre-enumerated. Dynamically definable:

| Structure | Definition |
|---|---|
| **ActiveBinding** | PortBinding with ≥1 wire instance in graph |
| **LatentBinding** | PortBinding declared but not yet wired (gap) |
| **WireAlgebra** | Selected subset of PortBindings — defines valid compositions |
| **BindingCategory** | Full subcategory induced by WireAlgebra |
| **BindingCooperad** | Coslice(root) filtered to WireAlgebra — cooperad fan-out |

The `broad_category` groups in ontology.json are *instances* of BindingCategories —
not the definition. The Slice tab in Explorer 2.0 is the first visual manifestation.

---

### PortFunctor — Cross-Category Path Finding

F: BindingCat_A → BindingCat_B exists iff a composable PTP sequence connects A's
objects to B's. This is the mechanism for assessing new routes in the user graph
from within the HG using projection:

```
1. Project: root nodes → all PTPs        (FUN10 PortInventory, proposed)
2. Partition: PTPs → BindingCategories  (FUN11 BindingCat, proposed)
3. Test: F: A → B?                       (FUN12 PortFunctor, proposed)
4. Materialize: LINK morphisms along path → graph state changes
```

Natural transformations between PortFunctors = symmetries of the path (different routes,
same state change). This is the Wolfram multiway system's causal invariance, now at the
BindingCategory level.

IRL systems (Docker, Python/PyTorch, filesystem, protein interfaces, mycelium junctions)
are already hypergraph-structured. They have PTPs. They are not unstructured — they are
**ungated**. Opening IRL topology = running FUN10 across gated systems, materializing
their PortBindings as S1 nodes.

**Semantic metric = Ricci curvature / port diameter:**
Nodes with many converging PTPs = high positive Ricci curvature = semantic cores (Rome).
Port diameter = geodesic distance. Semantic distance = structural distance = wire hops.
In HDC: φ(node) = ⊕{wires} already encodes this. Semantic distance IS structural
distance — not metadata, it is topology.
